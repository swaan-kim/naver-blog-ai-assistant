# AI 냠냠 v2, 여기서 바로 시작합니다

지금은 **문제별 허브 1편과 비교용 제안 원고 3편**이 준비돼 있습니다. 제안 원고는 v2 양식을 확인하는 예시이며, 사실 확인일과 발행 기한을 다시 확인하고 주인장의 주제·목차 승인을 받기 전에는 네이버 준비 단계로 넘어갈 수 없습니다.

공개 블로그 이름은 유지하고 소개 문구만 다음처럼 바꿉니다.

> AI는 쉽게, 업무 적용은 직접 확인합니다. 기획·마케팅·운영 실무자를 위한 AI·AX 실험 기록.

## 먼저 고를 것

| 번호 | 독자가 던질 질문 | 읽고 얻는 것 | 역할 |
|---|---|---|---|
| 1 | 회사 견적서를 AI에 통째로 올려도 될까? | 원본 대신 목적에 필요한 정보만 남기는 가상 예시 | 안전한 AI entry |
| 2 | AI로 PPT를 만들 때 첫 장에 어떤 숫자를 남길까? | 판단을 요청하는 3장 목차와 복사할 요청문 | 반복 업무 entry |
| 3 | AI 회의록은 끝났는데 금요일까지 누가 할까? | 결정·할 일·담당·기한을 뽑는 요청문 | 반복 업무 proof |

이 세 글을 최신 인기 주제로 단정하지 않습니다. 먼저 `이번 주 AI 냠냠 시작`으로 최근 14일 후보를 다시 확인하고, 기존 제안이 여전히 유효할 때만 선택합니다. 조회수는 보장하지 않으며 첫 달은 기준선을 만드는 기간입니다.

아래처럼 답하면 바로 다음 단계로 진행할 수 있습니다.

```text
1번으로 진행. 제목과 목차 승인.
```

수정하고 싶다면 짧게 지정해도 됩니다.

```text
2번 제목은 더 직관적으로. 4번째 소제목만 짧게 수정.
```

## 한 편이 통과해야 하는 기준

주제를 고를 때는 다음 항목을 봅니다. 이 항목은 검색 성과 예측값이 아니라 근거 없는 주제를 거르기 위한 기준입니다.

1. 독자가 실제로 묻는 질문이 선명한가
2. 읽은 뒤 할 수 있는 판단이나 행동이 구체적인가
3. 최근성 또는 오래가는 근거가 있는가
4. 보도자료를 옮긴 글이 아닌 주인장만의 관점이 있는가
5. 직접 캡처·전후 비교·실패와 수정·작은 실험 중 고유 증거가 가능한가
6. 같은 문제의 `entry → proof` 글로 연결할 이유가 있는가

공식 또는 1차 근거와 고유 증거가 없거나 가짜 사용 경험이 필요하면 버립니다. 원고에는 **구체적인 장면 1개, 한계 1개, 독자가 다시 쓸 수 있는 도구 1개**가 있어야 합니다.

## 제안에서 발행까지

```text
제안 검증 → 주제·제목·목차 승인 → 실제 목차로 상태 전환
→ 네이버 새 편집기 준비 → 주인장 최종본 승인 → 정확히 "발행"
→ 발행 URL 확인 → 문제별 허브·의미상 다음 링크 갱신
```

- `proposal`: 비교용 제안입니다. 목차 URL이 비어 있어도 되며 네이버 준비가 차단됩니다.
- `draft`: 주제·제목·목차가 승인되고 실제 목차 URL이 들어간 상태입니다.
- `final-approved`: 네이버 화면에서 최종본을 확인한 상태입니다. 그래도 현재 대화의 정확한 `발행` 명령이 한 번 더 필요합니다.

제안 원고 하나를 확인하는 명령은 다음과 같습니다.

```powershell
python skills/naver-blog-assistant/scripts/validate_package.py `
  pilot/posts/2026-11-19-company-file-ai `
  --index pilot/content-index.json --stage proposal --json
```

승인 후에는 `brief.md`의 `제안 목차`를 `승인된 목차`로 바꾸고 승인 상태를 갱신합니다. 목차 글을 먼저 발행해 실제 `hub_url`을 넣은 뒤 `--stage prepare`가 통과해야 네이버를 엽니다.

## 현재 준비 상태

- [ ] 프로필 소개 문구 변경
- [ ] 문제별 허브 제목·목차·최종본 승인
- [ ] 허브 발행 URL 확보
- [x] 제안 원고 3편의 출처·구조·미디어 준비
- [x] 제안 원고의 기준일·플랜·배포 범위 재확인 (2026-11-19)
- [ ] 첫 원고 선택 및 제목·목차 승인
- [ ] 네이버 편집기에서 최종 검수
- [ ] 정확한 `발행` 명령

기존 글 9편과 다른 임시저장 글은 이 파일럿에서 수정하지 않습니다. 기존 글은 새 허브·관계 계산·성과 비교에서도 제외합니다.

목차 글도 제목·목차 승인 없이는 준비 단계가 통과하지 않습니다.

- 제목·목차 승인: `hub/brief.md`의 `title_status`, `outline_status`를 `approved`로 바꾸고 `hub/draft.md`의 `outline_approved`를 `true`로 맞춥니다.
- 최종본 승인: `final_status`와 `final_approved`를 승인 상태로 맞추고 draft 상태를 `final-approved`로 바꿉니다. 실제 발행은 그래도 정확한 `발행` 명령이 있어야 합니다.

```powershell
python skills/naver-blog-assistant/scripts/validate_hub.py `
  pilot/hub --index pilot/content-index.json --stage prepare --json
```
