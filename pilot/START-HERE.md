# AI 냠냠, 여기서 바로 시작합니다

지금은 **목차 글 1편과 제안 원고 3편**이 준비돼 있습니다. 제안 원고는 내용·출처·이미지까지 검증할 수 있지만, 주인장의 주제·목차 승인을 받기 전에는 네이버 준비 단계로 넘어갈 수 없습니다.

## 먼저 고를 것

| 번호 | 독자가 던질 질문 | 읽고 얻는 것 | 역할 |
|---|---|---|---|
| 1 | ChatGPT가 발표자료까지 만들까? | 지금 써볼 계정인지, 무엇을 검수할지 판단 | 최신 유입 |
| 2 | AI를 쓰는데 왜 자료 찾느라 바쁠까? | 프롬프트보다 먼저 고칠 업무 병목 3개 | 신뢰·인사이트 |
| 3 | 회사 파일을 AI에 올려도 될까? | 첨부 전 확인할 5문항 체크리스트 | 오래가는 검색 |

첫 글은 **1번**을 추천합니다. 가장 최근 발표라 관심을 끌기 쉽고, 2번의 업무 구조 이야기와 3번의 안전 체크리스트로 자연스럽게 이어집니다. 조회수는 보장하지 않으며, 첫 달은 형식별 기준선을 만드는 기간입니다.

아래처럼 답하면 바로 다음 단계로 진행할 수 있습니다.

```text
1번으로 진행. 제목과 목차 승인.
```

수정하고 싶다면 짧게 지정해도 됩니다.

```text
2번 제목은 더 직관적으로. 4번째 소제목만 짧게 수정.
```

## 한 편이 통과해야 하는 기준

주제를 고를 때는 다음 다섯 항목을 각각 0~2점으로 봅니다. 이 점수는 검색 성과 예측값이 아니라 대화를 빠르게 하기 위한 우선순위 도구입니다.

1. 독자가 실제로 묻는 질문이 선명한가
2. 읽은 뒤 할 수 있는 판단이나 행동이 구체적인가
3. 최근성 또는 오래가는 근거가 있는가
4. 보도자료를 옮긴 글이 아닌 주인장만의 관점이 있는가
5. 다음에 읽을 글과 연결할 이유가 있는가

7점 이상을 우선 제안하되, 가짜 사용 경험이나 근거 없는 확신이 필요하면 점수와 무관하게 버립니다. 원고에는 **구체적인 장면 1개, 한계 1개, 다시 쓸 수 있는 체크리스트·판단법·작은 실험 1개**가 있어야 합니다.

## 제안에서 발행까지

```text
제안 검증 → 주제·제목·목차 승인 → 실제 목차로 상태 전환
→ 네이버 새 편집기 준비 → 주인장 최종본 승인 → 정확히 "발행"
→ 발행 URL 확인 → 목차·이전/다음 링크 갱신
```

- `proposal`: 비교용 제안입니다. 목차 URL이 비어 있어도 되며 네이버 준비가 차단됩니다.
- `draft`: 주제·제목·목차가 승인되고 실제 목차 URL이 들어간 상태입니다.
- `final-approved`: 네이버 화면에서 최종본을 확인한 상태입니다. 그래도 현재 대화의 정확한 `발행` 명령이 한 번 더 필요합니다.

제안 원고 하나를 확인하는 명령은 다음과 같습니다.

```powershell
python skills/naver-blog-assistant/scripts/validate_package.py `
  pilot/posts/2026-10-18-chatgpt-slides `
  --index pilot/content-index.json --stage proposal --json
```

승인 후에는 `brief.md`의 `제안 목차`를 `승인된 목차`로 바꾸고 승인 상태를 갱신합니다. 목차 글을 먼저 발행해 실제 `hub_url`을 넣은 뒤 `--stage prepare`가 통과해야 네이버를 엽니다.

## 현재 준비 상태

- [ ] 목차 글 제목·목차·최종본 승인
- [ ] 목차 글 발행 URL 확보
- [x] 제안 원고 3편의 출처·구조·미디어 준비
- [ ] 첫 원고 선택 및 제목·목차 승인
- [ ] 네이버 편집기에서 최종 검수
- [ ] 정확한 `발행` 명령

기존 글 9편과 다른 임시저장 글은 이 파일럿에서 수정하지 않습니다.

목차 글도 제목·목차 승인 없이는 준비 단계가 통과하지 않습니다.

- 제목·목차 승인: `hub/brief.md`의 `title_status`, `outline_status`를 `approved`로 바꾸고 `hub/draft.md`의 `outline_approved`를 `true`로 맞춥니다.
- 최종본 승인: `final_status`와 `final_approved`를 승인 상태로 맞추고 draft 상태를 `final-approved`로 바꿉니다. 실제 발행은 그래도 정확한 `발행` 명령이 있어야 합니다.

```powershell
python skills/naver-blog-assistant/scripts/validate_hub.py `
  pilot/hub --index pilot/content-index.json --stage prepare --json
```
