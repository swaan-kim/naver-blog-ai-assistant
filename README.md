# AI 냠냠 · 네이버 블로그 조수

**독자가 궁금한 주제를 고르고, 주인장의 목소리로 쓰고, 발행 직전까지 안전하게 준비하는 파일 중심 Codex 스킬입니다.**

솜솜은 조사·검증·편집을 맡는 내부 조수입니다. 공개 글에서는 캐릭터가 대신 말하지 않고 주인장이 직접 경험하고 판단한 것처럼 씁니다.

> 이 브랜치는 8편 파일럿용입니다. 검증이 끝나기 전에는 공개 `main` 설치판을 바꾸지 않습니다.

## 한눈에 보기

```text
“이번 주 AI 냠냠 시작”
→ 후보 5개
→ 주제 선택
→ 제목 3개·목차 승인
→ brief.md
→ draft.md 한 번 생성
→ 필요한 문단만 수정
→ 로컬 검증
→ 네이버 편집기 준비
→ 최종 승인
→ 정확히 “발행”
→ 발행·목차·이전 글 링크 갱신
```

주제, 목차, 최종 원고는 사람이 승인합니다. AI가 글을 완성해도 `발행`이라는 현재 작업의 정확한 명령이 없으면 발행하지 않습니다.

## 세 가지 글 형식

| 형식 | 언제 쓰나요? | 기본 분량 |
|---|---|---:|
| `3분 AI 정리` | 새 발표·연구·정책을 쉽게 설명 | 900–1,400자 |
| `직접 써봤습니다` | 주인장이 실제 사용한 도구 후기 | 1,500–2,100자 |
| `자료를 확인해봤습니다` | 직접 써보기 어려운 정책·연구 확인 | 1,500–2,100자 |

추천은 직접 사용한 경우에만 합니다. 후기에는 `처음 써봄`, `몇 번 써봄`, `계속 쓰는 중` 중 하나와 다음 네 가지 원재료가 필요합니다.

- 무엇을 하려고 썼는지
- 무엇이 편했는지
- 어디서 막혔는지
- 다시 쓸 것인지

## 파일은 세 가지만 유지합니다

```text
content/
├─ content-index.json
└─ posts/
   └─ YYYY-MM-DD-slug/
      ├─ brief.md
      └─ draft.md
```

- `brief.md`: 독자 질문, 출처, 승인 목차, 주인장 경험 메모
- `draft.md`: 네이버에 입력할 최종 원고와 이미지·링크 메타데이터
- `content-index.json`: 상태, 발행 URL, 목차·이전·짝 글 관계

원문 페이지 전문이나 네이버 DOM은 저장하지 않습니다. 템플릿은 [brief](skills/naver-blog-assistant/assets/brief-template.md), [draft](skills/naver-blog-assistant/assets/draft-template.md), [index](skills/naver-blog-assistant/assets/content-index-template.json)에서 시작합니다.

## 바로 쓰는 요청문

### 이번 주 후보 받기

```text
$naver-blog-assistant로 이번 주 AI 냠냠 시작.
최근 14일 공식 발표와 오래가는 실용 질문을 확인해 후보 5개만 보여줘.
아직 원고는 쓰지 마.
```

### 선택 후 목차 만들기

```text
2번 주제로 진행하자.
근거와 제목 후보 3개, 목차만 제안해줘.
내가 목차를 승인하기 전에는 draft.md를 만들지 마.
```

### 실제 사용 후기의 원재료 주기

```text
목적은 회의 자료 요약이었고, 긴 글의 핵심을 찾는 건 편했어.
표가 깨진 곳에서 막혔고, 짧은 문서에는 다시 쓸 생각이야.
처음 써봄으로 기록해줘.
```

### 네이버에 준비하기

```text
검증된 draft.md를 네이버 새 편집기에 준비해줘.
기존 글은 건드리지 말고 발행하지 않은 채 검수 화면에서 멈춰줘.
```

최종본을 확인한 뒤 현재 글에 `발행`이라고 정확히 요청해야 실제 발행 단계로 넘어갑니다.

## 로컬 검증

초안만 빠르게 확인합니다.

```powershell
python skills/naver-blog-assistant/scripts/validate_draft.py content/posts/YYYY-MM-DD-slug/draft.md --json
```

승인·경험 메모·링크·콘텐츠 인덱스까지 함께 확인합니다.

```powershell
python skills/naver-blog-assistant/scripts/validate_package.py content/posts/YYYY-MM-DD-slug `
  --index content/content-index.json --stage prepare --json
```

발행 직전에는 `--stage publish`로 다시 검사합니다. `[[확인 필요]]`, 제목 중복, 분량·소제목 오류, 이미지 누락, API 키로 보이는 문자열이 있으면 차단합니다. 출력은 원고 대신 제목·글자 수·문단 수·오류 코드만 반환합니다.

## 토큰을 아끼는 구조

```text
원고를 채팅과 브라우저 사이에 반복 전달
                ↓
draft.md 한 번 생성 → 부분 수정 → 로컬 검사 → 파일 경로로 입력
```

- `SKILL.md`는 작업을 구분하는 짧은 라우터만 유지합니다.
- 기획·작성·브라우저·월말 회고 지침은 필요한 때에만 읽습니다.
- 글자 수, 중복, 미해결 표시 같은 결정형 검사는 Python이 처리합니다.
- 정상 브라우저 경로에서는 전체 DOM·스크린샷·원고 전문을 모델에 돌려주지 않습니다.

각 실행 경로의 `SKILL.md + 참고 문서`는 Windows 줄바꿈을 포함해 4,000자 이하인지 테스트합니다.

## 표지와 이미지

글마다 표지 1개와 실제 화면 또는 설명 도식 1개만 사용합니다. 기존 강아지 솜솜 원본이 없으면 새 캐릭터를 만들지 않고 임시 텍스트 표지를 사용합니다. AI로 생성하거나 편집한 이미지가 있으면 `ai_media: "true"`로 기록해 네이버의 `AI 활용` 설정을 적용합니다.

## 링크와 실패 처리

새 글에는 새 목차 글과 직전 글 또는 짝 글 링크를 넣습니다. 발행 후 목차와 직전 새 글의 다음 링크를 갱신합니다. 기존 아홉 편은 수정하지 않습니다.

링크 갱신이 실패해도 새 글을 다시 발행하지 않습니다. 발행 URL과 `PARTIAL_LINK_UPDATE` 상태를 남기고 사람이 이어서 고칩니다.

## 월말 회고

네이버 통계에서 조회수, 유입 경로·검색어, 재방문율, 평균 방문 횟수, 댓글·공감, 이웃 순증만 직접 확인합니다. 이를 CTR이나 완독률로 바꾸어 부르지 않습니다. 첫 달은 기준선만 만들고 이후에는 같은 형식끼리 비교해 `유지 1개 / 변경 1개 / 실험 1개`만 결정합니다.

[월간 회고 템플릿](skills/naver-blog-assistant/assets/monthly-review-template.md)을 사용하세요.

## 안전 원칙

- 로그인과 인증은 사용자가 직접 합니다.
- 비밀번호, 인증번호, 쿠키, 세션, API 키를 글이나 Git에 넣지 않습니다.
- 셀렉터가 맞지 않으면 좌표를 추측하지 않고 중단합니다.
- 의료·법률·금융·정치는 공식 자료와 독립 출처가 함께 있을 때 현상만 설명합니다.
- 8편 파일럿에서 허위 경험·출처 오류·오발행 0건을 확인한 뒤에만 공개 스킬을 갱신합니다.
