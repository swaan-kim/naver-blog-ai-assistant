# Content contract

Read this file before drafting or revising a post.

## Six required inputs

Establish these fields before writing:

1. AI concept or tool to explain
2. Real problem the reader experiences
3. One-sentence conclusion
4. Directly verified facts and environment
5. Official document, primary source, or direct experiment to cite
6. Point where a person must make the final judgment

If a field is missing, infer only when the choice is reversible and low risk. Label inferred details in the review notes. Never invent measurements, usage results, or citations.

## Default series profile

Use this profile when the user does not provide another house style:

- Audience: readers curious about AI but unfamiliar with technical terms
- Length: 1,800-2,200 Korean characters excluding tags
- Voice: follow `somsom-persona.md`
- Paragraphs: one to three sentences each
- Headings: four to six, with a blank paragraph before each heading
- Emoji: only in headings or explanation callouts
- Humor: short and limited to the opening or failure scenes
- Accuracy: more important than cheerfulness
- Formatting: Nanum Gothic 15 pt, left aligned, 180% line spacing when the editor supports it
- Default category: `AI 잡학 쩝쩝`

## Default article structure

1. Familiar problem and reader benefit: 120-180 characters
2. Prerequisite concept and one-line definition: 200-300 characters
3. Why the concept matters: 200-300 characters
4. Familiar approach versus new approach: compact table plus a short interpretation
5. Practical flow: five to seven numbered steps
6. Failure, constraint, and validation: 250-350 characters
7. Observed result and unverified limits: 200-250 characters
8. One-sentence takeaway and next question: 100-150 characters

Use one visual structure in the body: a compact comparison table, flow line, or short command example. When comparing two concepts, prefer a native table with four to six criteria. Prefer an indented quotation/callout block for a one-line process flow.

## Title and tags

- Title pattern: curiosity or problem + technical reward
- Title length: 25-40 Korean characters when practical
- Common tags: choose three stable series tags
- Article tags: add three or four topic-specific tags
- Avoid duplicate tags and claims disguised as tags

## Review rules

- Keep observed facts separate from interpretation.
- State unmeasured effects as unmeasured.
- Explain a technical term on first appearance.
- Do not place two unexplained technical terms consecutively.
- Do not imitate sentences from a reference article; borrow only high-level structure.
